# Changelog for version 2.1.312

## Summary

Version 2.1.312 adds a clickable “send now” control and improves explanations when auto mode cannot review an action. It also tightens file replacement and permission handling: replacing a file after reading only its beginning can now be refused, and hooks cannot approve certain skill-loading requests on your behalf.

## New Features


### Click to Send a Queued Message Now

In fullscreen terminals with mouse support, the “send now” hint is now clickable, letting you deliver a queued message immediately while Claude is working. The hint respects your `chat:sendNow` keybinding, including an explicit unbinding.

## In Development


### Cloud-Session Activity and Disconnect Controls

The existing cloud folder-serving feature gains a more detailed terminal status display: connected and connecting sessions, running tools and elapsed time, approval waits, and idle connections. It also adds an `x` disconnect action: press it again within five seconds to disconnect cloud sessions from the folder; another key cancels.

Folder serving remains controlled by `tengu_violin_luthier`, whose default is off. These controls require that feature to be available for your account.

Serving helpers also gain idle release, normally after 60 minutes without tool activity, with timing controlled by `tengu_violin_sordino`. Running calls, pending approvals, and background work prevent idle release; a released session can request access to the folder again.


### Restoring Skill Instructions After Restart

Behind `tengu_soft_spark`, off by default, Claude Code records directly invoked skills in the conversation and reconstructs their instructions when restoring context. This should help resumed sessions retain the skill guidance they were following before a restart or compaction.


### Awareness of Files Still Being Copied

Behind `tengu_ochre_dunlin`, off by default, cloud sessions can tell Claude that attached files are still being copied. The new guidance distinguishes a pending copy from a failed upload, reducing premature “file missing” reports and requests to attach the same file again.

## Other Changes

- Changed Write to refuse whole-file replacement when Claude has received only the beginning of the file and has not subsequently read it completely.
- Changed auto-mode handling of missing safety verdicts to request human approval where supported, explain when approval is unavailable, and stop repeated unsuccessful attempts.
- Changed auto-mode review handling so hook or plugin changes to tool inputs invalidate reviews that no longer cover what would execute.
- Changed MCP-served skill approval so a plugin cannot substitute its own approval when a person must approve loading the skill.
- Changed hook loading in untrusted workspaces to exclude project-controlled hooks that the user’s own settings do not authorize.
- Improved Windows file protections around alternate path spellings, links, and short filenames that could resolve into Claude Code’s executable configuration directories.
- Added a warning when project settings contain ignored claude.ai sign-in variables, directing users to their shell or `~/.claude/settings.json`.
- Improved remote permission handling to explain when this terminal cannot display or answer a request and when Escape can stop the waiting turn.
- Improved cloud restart recovery for interrupted subagent calls, distinguishing resumed work from finished agents whose reports were lost.
- Improved automatic-continuation warnings after repeated usage-limit hits, with `/rate-limit-options` identified as the way to try again.
- Improved fast-mode messages to distinguish exhausted credits from credits unavailable for the account, plan, or organization.
- Improved cloud WebFetch failures to explain that unresolved hosts may be outside the session’s allowed network domains.
- Improved date guidance in UTC-based cloud sessions to distinguish the UTC date from the user’s local date.
- Fixed Artifacts MCP file publishing failing to honor applicable Read permission restrictions.
- Fixed MCP skill-loading approval controls allowing acceptance before the required consent surface was ready.
- Removed the experimental interactive-workshop planning path and its special permission to edit and publish a workshop document during plan mode.

## Notes

If Claude refuses a whole-file replacement after a partial read, ask it to use Edit for a targeted change or read the complete file before replacing it.

If auto mode reports that its safety check is unavailable, review any approval prompt yourself or switch permission modes with `Shift+Tab`. If a hook repeatedly changes the requested input, review that hook before retrying.
