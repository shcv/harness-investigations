#+TITLE: Claude Code changelog model replay, 2026-09-13

* Question

Would stronger Codex models recover the user-facing changes that the existing
Terra-based changelog workflow missed in Claude Code 2.1.242--2.1.245, using the
same candidate build from =../astdiff-changelog=?  A later check also asks
whether the archived 2.1.170 changelog is correct.

* Controlled setup

- Models: =gpt-5.6-sol= and =gpt-6-astra=, both at =medium= reasoning.
- Diff implementation:
  =/home/shcv/.local/lib/harness-investigations/astdiff/239893c-changelog-2d340ca5ca52/astdiff=.
- The replay archives were isolated from one another.  Prompts explicitly
  prohibited reading archived changelogs, prior audits, replay reports, and
  Codex memory.  An audit of all eight event logs found no command that read
  those paths.
- Each run could inspect the filtered astdiff, string diff, and the old and new
  pretty-printed bundles.  This tests semantic interpretation after diff
  construction; it does not test a model forced to use only the diff.
- Full prompts, tool calls, outputs, metadata, and final answers were copied out
  of the runner's rotating log directory immediately after each run.

The runner records =read_roots= as provenance, but the Codex backend currently
uses a filesystem-wide read-only sandbox and does not enforce those roots.
Isolation in this experiment therefore comes from the prompt and the trace
audit, not an operating-system access boundary.

* 2.1.170 audit

The archived 2.1.170 changelog was broken in several material ways.  It was not
wholly fabricated: Fable is an official release highlight, and many of its
lower-level observations are real.  The errors were:

1. It called =model_refusal_fallback= a new emitted event.  Version 2.1.169
   already emitted the event; 2.1.170 exports its schema and enriches metadata.
2. It missed the highest-impact refusal change.  The old eligibility function
   required the default-off =tengu_loggia_carousel= gate; the new function only
   checks =CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=.
3. It reduced the official VS Code/inherited-environment repair to prompt
   history.  Removing the shared =HkH()= predicate also restores transcript
   persistence and session registration, which makes =--resume= work.
4. It reversed the credit-required 429 exception.  =fetch_error= and
   =org_level_disabled_until= continue through ordinary retry handling; the
   other matching credit-required responses are non-retryable.
5. It presented Fable as universally available.  The CLI checks account and
   provider model options and can report it unavailable.
6. Its provenance names =changes-v2.1.170-2.md=, which is not present in the
   current archive, so the exact generation input cannot now be resolved.

The new candidate astdiff matches 25,724 of 25,753 declarations (99.7%), with
66 additions, 29 removals, 10,620 structural changes, and 37 string-only
changes.  That confirms the matcher is working, but it also leaves a very large
semantic review surface.

A clean Sol replay found the Fable availability boundary, refusal-gate removal,
server-fallback tombstone handling, and dark task-continuity prompt.  It omitted
the official transcript/resume fix and several valid secondary changes.  Astra
gave the more complete 2.1.170 result, including persistence, model handling,
fallback behavior, caching, picker behavior, and tombstone cancellation.  The
source-checked correction is now the canonical
[[file:../archive/claude-code/changelog/changelog-v2.1.170.md][2.1.170 changelog]].

* Workflow repair

The npm/GitHub split exposed a separate pipeline error: official GitHub release
notes were fetched only for projects whose source artifact also came from
GitHub.  Claude Code artifacts come from npm, so the generator never received
the published =anthropics/claude-code= baseline.  =ProjectConfig= now has an
independent release-notes repository and tag prefix, with Claude Code mapped to
=anthropics/claude-code= and =v=.  Existing GitHub projects inherit their source
repository defaults.

The practical workflow should be:

1. Use the candidate astdiff and retain its provenance and coverage metrics.
2. Put official release notes first as a published baseline, even when the
   source artifact comes from another registry.
3. Require each material prose claim to identify old and new source evidence.
4. Reject a no-change or low-impact answer when the diff contains high-signal
   added settings, environment variables, CLI options, gates, or registrations.
5. Keep the full session trace and run an acceptance review before publication.
6. Enforce read roots in the runner rather than only recording them.

A stronger model is useful for the semantic pass.  It does not replace those
controls: both models consumed millions of cumulative input tokens and dozens
of tool calls, and the 2.1.170 Sol run still missed the official headline fix.

The scheduled service now uses =gpt-6-astra= at medium for the main changelog
pass and =gpt-5.6-luna= at low for its optional annotation pass.  The
evidence-aware acceptance checks remain necessary despite the stronger writer.
