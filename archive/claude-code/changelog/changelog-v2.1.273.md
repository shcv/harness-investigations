# Changelog for version 2.1.273

## Summary

Compared with v2.1.272, this version adds tool exclusions within `--tools`, Remote Control inbox-reading support, and clearer authentication and configuration diagnostics. It also strengthens shell permission checks, improves scheduled-task ownership checks and macOS file reads, and ships gated work on an alternative diff pane and recovery after a stopped response.

## New Features


### Remote Control Inbox Reading [Gradual Rollout]

What: Connected Remote Control sessions can read messages relayed from linked chat or project threads using the new `FetchInboxMessage` tool.

Usage: When a session receives an inbox notification, Claude can retrieve the message using its `file_id`.

Details:

- The transcript initially receives a notification; fetching displays the sender and message content.
- Reading this session’s inbox does not open a permission dialog.
- Messages marked by the tool as `from="rc_owner"` represent a server-verified request from the session owner. Other messages remain third-party content.
- Requires an active Remote Control connection or supervised bridge session, valid authentication, and server support for the organization.
- Unavailable, expired, or other-session messages return an explanatory error.

Evidence: New tool registration and implementation, absent from both previous-version sources; search for `"FetchInboxMessage"`, `"message.received"`, and `"The session inbox isn't enabled for this organization"`.


### Control Request-Hint Headers

What: `CLAUDE_CODE_GATEWAY_HINT_HEADERS` controls whether requests include additional context about the work Claude Code is performing.

Usage:

```bash
CLAUDE_CODE_GATEWAY_HINT_HEADERS=0 claude
```

Details:

- An explicit environment value overrides the default.
- Hints include request classification, compaction information, and previous tool execution durations.
- The standard first-party route enables these hints by default; other first-party routes consult `tengu_splendid_sutton`. Other providers default to disabled unless explicitly enabled.
- This changes request metadata; it does not add a new model or gateway connection.

Evidence: New environment-variable check and header emitters; search for `"CLAUDE_CODE_GATEWAY_HINT_HEADERS"`, `"x-claude-code-context-compacted"`, and `"x-claude-code-prev-tool-durations"`.

## Improvements


### Exclude Individual Tools from a Preset

The existing `--tools` option now accepts `!ToolName` exclusions, allowing you to start with the default tool set and remove selected tools.

Usage:

```bash
claude --tools 'preset:default,!Bash,!Edit,!Write'
```

Details:

- Exclusions remove whole tools.
- An entry such as `!Bash(git *)` produces a warning and excludes all of Bash; it is not a command-scoped permission rule.
- Missing names, spaces after `!`, and unknown built-in tool names receive specific diagnostics.
- An exact-name MCP tool is also withheld when named by an exclusion.
- Enabled by default unless `tengu_tools_exclusion_killswitch` is activated.

Evidence: New exclusion parser integrated into tool selection; search for `"tengu_tools_exclusion_killswitch"`, `"names a rule, not a tool"`, and `"matches no built-in tool"`.


### More Actionable MCP Authentication and Disconnection Messages

MCP tool-call failures now distinguish between expired sign-in, a rejected configured `Authorization` header, and a rejected credential generated by `headersHelper`.

The recovery message points to the appropriate action: update the configured header, fix the helper, reconnect through `/mcp`, or re-authenticate. Failed automatic reconnection also produces a visible notification directing users to `/mcp`.

Evidence: Updated tool-call error handling and reconnection notifications; search for `"rejected the credential from its headersHelper"`, `"rejected the Authorization header in its config"`, and `"disconnected · open /mcp to reconnect"`.


### Provider-Specific Authentication Guidance

Authentication errors now offer more specific recovery guidance for Amazon Bedrock, Google Cloud, Microsoft Foundry, and gateways.

Details:

- AWS failures distinguish invalid credentials from model-access problems where the error provides that information.
- Google Cloud messages point to credential refresh and relevant access checks.
- Foundry messages identify supported credential sources and resource-access checks.
- A gateway refusal can explicitly explain that signing in again will not resolve the problem.
- Host-managed credentials receive administrator-oriented guidance.

Evidence: Provider-specific authentication-error branches; search for `"Microsoft Foundry authentication failed"`, `"refresh your AWS credentials"`, `"refresh your Google Cloud credentials"`, and `"signing in again won't change this"`.


### GitHub SSO Setup Diagnostics

`/install-github-app` now identifies SAML single sign-on enforcement separately from missing repository administration privileges.

The message explains how to re-authorize GitHub CLI access with the required scopes or authorize a personal access token for the organization, then retry setup.

Evidence: New `saml_enforcement` branch in the existing setup flow; search for `"Single sign-on authorization needed"` and `"Authorize the organization when GitHub prompts for single sign-on"`.


### Better Explanations for Managed Settings

Configuration diagnostics now identify MCP policy keys that were ignored because they came from a managed source that does not govern those keys. Messages direct users to `/status` and identify where the setting should be changed.

The managed-settings approval dialog also gains wording specifically for virtual-machine isolation settings, explaining that they can change where Claude Code runs or what it can connect to.

Evidence: Settings-source diagnostics and isolation-specific dialog text; search for `"is not the managed settings source that applies"` and `"Your organization has configured virtual machine (VM) isolation settings"`.


### Unknown Slash Commands Can Fall Back to a Request in Cloud Sessions

In eligible noninteractive cloud sessions, an unknown slash command can now be passed to Claude as an ordinary request instead of ending with an unknown-command error.

Details:

- Claude receives explicit notice that the command did not run.
- Context includes available commands and a close-match suggestion when one exists.
- Policy-blocked commands and unavailable built-in commands retain their explicit handling.
- The fallback is enabled by default in this lane unless `tengu_polished_quill_killswitch` is activated.

Evidence: New fallback attachment and cloud-only dispatch condition; search for `"unknown_command_fallback"`, `"tengu_polished_quill_killswitch"`, and `"Treat the message as a plain request"`.


### Clearer Artifact Editing and Publishing Instructions

For sessions that already expose Artifact tools, the bundled instructions now describe deleting individual database fields during an update:

```json
{
  "obsoleteField": {
    "__delete__": true
  }
}
```

The instructions specify that the marker works at nested field depths, is rejected inside arrays, and is not accepted by `set`.

Publishing errors also give clearer guidance for unsupported files, mismatched content types, and text files that should be served as `text/plain`. Documents and archives remain unsupported as attachments through this publishing path.

Evidence: Updated Artifact tool instructions and validation messages; search for `"__delete__"`, `"Nothing was published because one file is of a type artifacts don't serve"`, and `"A source, config, log or other text file goes as text/plain"`.

## Bug Fixes

- **Scheduled tasks copied from another checkout are less likely to run unintentionally.** When considering tasks owned by another session and lacking explicit project identity, the scheduler now checks for that creator’s transcript in the current project’s transcript directory. Tasks without that evidence are not adopted. Search for `"scheduled_tasks.json (a file copied from another checkout looks like this)"`.

- **Fewer false file-read refusals on macOS.** When fresh path resolution differs from the approved spelling or cannot be rendered, the read path can verify the file’s device and inode identity and open an approved path without following links. This preserves the identity check while allowing equivalent-path cases. Search for `"openReadBoundToApproval"` and `"opened link-free"`.

- **Stricter handling of shell syntax the analyzer cannot safely interpret.** Additional declaration, assignment, `unset`, quoting, and Bash/Zsh parsing differences are classified as too complex rather than treated as inert text. Search for `"carries a subscript or escape the shell evaluates"` and `"with an operand bash would evaluate as a compound array assignment"`.

- **Git commands following directory changes receive broader detection.** The check now recognizes additional parsed command forms, including `xargs` invoking Git. The new “version-control” wording does not establish support for every version-control system: the additional generic detector remains stubbed in this build. Search for `"This command changes directory before running a version-control command"`.

- **Artifact publishing can recover from a lost response without blindly duplicating the publish.** Requests gain an attempt identifier and a marked resend path. If the server reports that the original publish is still settling, the client waits and retries within bounded limits. Search for `"/api/frame/deploy/direct?attempt_id="`, `"publish_settling"`, and `"re-sending it once, marked"`.

- **Project-thread replies receive a delivery check.** In supported Remote Control project-thread sessions, ending a turn without a successful reply action—or with a failed reply action—prompts Claude to complete the thread response or explicitly indicate that none is needed. The check defaults on through `tengu_rc_thread_reply_gate`. Search for `"plain text is not delivered there"` and `"tengu_rc_thread_reply_gate"`.

## In Development


### Alternative Diff Pane with Prompt Attachments [In Development]

What: A new plugin-based implementation of the existing `/diff` workflow includes a way to attach a selected file’s diff to the next prompt.

Status: Feature-flagged; `tengu_quiet_dolphin` defaults to false and also requires the function-hook/plugin infrastructure to be available.

Details:

- Includes a changed-file list, hunk viewer, and refreshes as Claude edits.
- Supports uncommitted, branch, session, and per-turn views.
- An “ask” action attaches the selected diff to the next prompt; selecting it again removes the attachment.
- Explicit opening requires at least 110 terminal columns.
- Oversized attached diffs are truncated with a notice.
- `/diff`, diff panels, and per-turn diff viewing already existed in v2.1.272. The new work is this implementation and its attachment behavior.

Evidence: New original module containing `"tengu_quiet_dolphin"`, `"rides your next prompt"`, and `"The user attached the diff of"`; compare the existing `"View uncommitted changes and per-turn diffs"` command in both versions.


### One-Time Continuation After a Stopped Response [In Development]

What: Claude Code can attempt one continuation on the same model after a response is stopped by a safety classifier, while explicitly recording what happened to pending tool calls.

Status: Feature-flagged; `tengu_ochre_kite` defaults to false. The source also recognizes `CLAUDE_CODE_OCHRE_KITE`.

Details:

- Adds a visible “continuing once” notice.
- Distinguishes tools that never ran from tools interrupted while running.
- Preserves the warning that interrupted calls may have partially or fully completed.
- Tells the model not to reproduce the withheld content.
- Excludes auxiliary requests and prevents repeated use of this continuation path.

Evidence: New continuation logic and tool-result messages; search for `"tengu_ochre_kite"`, `"continuing once with that noted"`, and `"Not run: the response that made this tool call was stopped by a safety classifier"`.
