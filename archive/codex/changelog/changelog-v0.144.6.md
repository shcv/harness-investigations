# Changelog for version 0.144.6

## Official Release Highlights

This is a hotfix release targeting GPT-5.6 Sol, Terra, and Luna. The bundled model metadata for these three models was corrected and their system instructions were refreshed.


### Context window correction for GPT-5.6 Sol, Terra, and Luna

What: The context window size for all three GPT-5.6 variants was corrected from 372,000 tokens to 272,000 tokens.

Details:
- Both `context_window` and `max_context_window` fields in the bundled model catalog were updated from 372,000 to 272,000 for `gpt-5.6-sol`, `gpt-5.6-terra`, and `gpt-5.6-luna`.
- The previous value of 372,000 was incorrect. 272,000 tokens is the accurate limit for these models.
- Any context-window-dependent behavior in Codex (auto-compaction thresholds, truncation warnings) will now reflect the correct limit.

Code references: `context_window` and `max_context_window` fields in `codex-rs/models-manager/models.json` for model slugs `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna`.


### Refreshed system instructions for GPT-5.6 Sol, Terra, and Luna

What: The bundled `instructions_template` and `base_instructions` for all three GPT-5.6 models were updated.

Details:
- These are the system-level instructions Codex injects when you use one of the GPT-5.6 model variants. The refreshed text reflects updated behavioral guidance from OpenAI.
- Changes affect both the templated form (used when building a new session) and the base form (used as the fallback when no personality variant is selected).

Code references: `instructions_template` and `base_instructions` fields in `codex-rs/models-manager/models.json` for `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna`.


## Additional Changes Beyond Official Notes

### GPT-5.6 Sol: reasoning-transparency paragraph removed

What: A paragraph instructing Sol to lead with "concrete evidence and diligent reasoning" when challenged was removed from the system prompt.

Details:
- The old instructions included the following between the personality description and the "Writing style" section:
  > "When presented with clarifying questions or objections from the user, lead with concrete evidence and diligent reasoning rather than unsubstantiated deference. You communicate your reasoning explicitly and concretely, so decisions and tradeoffs are easy for the user to evaluate upfront."
- This paragraph is absent from the refreshed instructions. The "## Writing style" section now follows directly after the personality description.
- In practice, Sol's communication style when pushed back on may feel less explicitly argumentative.

Code references: `instructions_template` and `base_instructions` for `gpt-5.6-sol` in `codex-rs/models-manager/models.json`.


### GPT-5.6 Terra and Luna: environment-variable safety guideline added

What: A new instruction was added to Terra and Luna warning against reusing system-reserved environment variable names.

Details:
- The new bullet appears in the shell-safety section of the prompt, immediately before "## File editing constraints":
  > "When declaring env vars or script variables, always avoid common system options. Never repurpose `$HOME`, `$home`, or `$CODEX_HOME`. Instead, use a task-specific variable name."
- This guards against accidental clobbering of `$HOME` or Codex's own `$CODEX_HOME` in shell scripts generated by the agent.
- The same guidance was already present in Terra and Luna's prompts for other restrictions; this adds the env-var case.

Code references: `instructions_template` and `base_instructions` for `gpt-5.6-terra` and `gpt-5.6-luna` in `codex-rs/models-manager/models.json`.
